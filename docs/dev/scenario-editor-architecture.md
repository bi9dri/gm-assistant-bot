# Scenario Editor Architecture (#213)

> **#213 系サブ issue の設計基準（進行中）。着手前に読むこと。**
> ここに書かれた決定は確定済みであり、実装中に再検討しない。誤りが判明した場合はコードを書く前に提起する。

## コンセプト

シナリオ本文を背骨にした段落ベースのリッチテキストエディタ（第 3 世代 UI）。
**本文は外部資料への参照ではなく、GM が進行用に再構成した成果物**とし、Discord 操作を段落中のインライン要素として差し込むことで、編集と実行の連続性を保つ。

## 確定済みの設計決定

| 論点                                        | 決定                                                                                                                                                                                                                                                                                                                                     |
| ------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| リッチテキスト基盤 (D6 / D23)               | **Tiptap (ProseMirror)** を採用。日本語 IME・undo・貼り付け・ホワイトリスト schema を任せる。自前 `contentEditable` と Markdown パーサは持たない（入力ルールで代替）。                                                                                                                                                                   |
| データ分離 (D25)                            | `ScenarioData = { version: 2, doc, steps }` とし、`doc` には `stepId` の参照だけを置く（孤児は保存時に除去）。`executedAt` 等の実行記録と本文の undo 履歴を分離するため。`steps` は `doc` の出現順配列（実行順 = 読む順）。                                                                                                              |
| 本文の表現力 (D20 / D24)                    | `paragraph` / `heading(1〜3)` / `bulletList` / `orderedList` / `blockquote` / `bold` / `highlight` + `step`（インラインアトム） + `branch`（ブロック）のみ。Callout・構造化ブロック（`Character` 等）・リンク・テーブル・インライン画像は当面作らない（シナリオ 3 本書き下ろすまで型を切らない）。                                       |
| registry・実行エンジン共有 (D7 / D10 / D11) | 既存 `StepRegistryEntry`・`DetailPanel`・`flow/engine/order.ts`・`flow/treeOps.ts`・`runnerStore` を無改造で再利用する。**Branch 降下ロジックや実行意味論を新画面用に書き直さない**。`Text` ステップは no-op の `execute()` で既存経路に乗せる。                                                                                         |
| 実行モードの本文 (D10)                      | 実行モードの本文は**読み取り専用**。「既読」などの別状態は持たない（`executedAt` に一本化）。                                                                                                                                                                                                                                            |
| ループ (D9)                                 | 専用 `Loop` ブロックは作らず、目次の「ここから再実行」で配下の `executedAt` / スキップ印をクリアする（既存 `treeOps.clearDescendantExecution` を利用）。周回数は既存 `Counter` で数える。                                                                                                                                                |
| 回遊・連携 (D13 / D19 / D22)                | 目次パネルを提供（全文展開前提のため折りたたみ・アプリ内全文検索は持たない）。CCFOLIA 連携はクリップボードコピー、本文取り込みは貼り付け主体＋`.txt`/`.md` 取り込み。                                                                                                                                                                    |
| 永続化・移行 (D4 / D14 / D16 / D26)         | `Template.scenarioData` / `GameSession.scenarioData` を新設。旧 `flowData` からの変換は行わない（`ScenarioData` v1 → v2 のみ変換）。セッション作成時の OPFS パス書き換え（`convertFilePathsInScenarioData`）とメタ情報カラム（人数・所要時間の上下限・システム・カバー画像パス）を追加。Dexie 変更時は `schema-migration` スキルを使う。 |
| ルーティングと旧 UI 併存 (D5 / D12 / D15)   | `/template/$id/scenario`・`/session/$id/scenario` のディレクトリルート形式を使う（**フラットな `$id.scenario.tsx` は禁止** — `$id.tsx` に `<Outlet/>` がなく描画されない）。`/template/new` は新形式のみ。旧 2 系統（React Flow / ステップリスト）は凍結し、新機能はすべて新画面にのみ実装する。                                         |

## 検証ポイント

- 純粋ロジック（`document.ts`, `migrate.ts`, `outline.ts`）はユニットテストで TDD する。
- 静止画 VRT で担保しきれない**日本語 IME 入力・貼り付け・文中への操作挿入**は、フェーズ 2 / 3 の受け入れで `verify` スキル（Playwright 実操作）で必ず確認する。

## スコープ外

- 投票の集計・配役（D17 / D18、#249 で保留）
- プレイ履歴（セッション側メタ）、CCFOLIA 駒データ出力、PDF 併置ビューア、共同編集（Y.js 等）
- 構造化ブロック（`Character` 等）・テーブル・インライン画像・リンク・Markdown パーサ
